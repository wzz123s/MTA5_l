## 一、修复清单

### BUG-1（致命）：空单确认因子 sign 符号错误 ✅ 已修复

**根因**：`way_s_way = way_s/way`、`vol_way_s_way = vol_way/way` 在 down 段里 x/y/z 都是负数，
负÷负=正，两个比值恒为无符号 [0,1]。确认因子写成 `sign * min(w1,w2) >= 0.5`，空单 sign=-1
恒为负 → 空单 100% 被否决，策略退化为纯多头（历史 315 次死叉 → 0 笔空单）。

**修复**：去掉 `sign *`，改为 `min(w1,w2) >= 0.5 && min(v1,v2) >= 0.5`（方向已由触发 good/bad 决定）。

## 四、⚠️ 关键发现（比符号 bug 更重要）

修复 BUG-1 是**正确且必须**的（让实现与文档一致、暴露真实风险敞口），但它揭示了一个更深层的问题：

**这个策略在 USOIL 2H 上，多头有 alpha，空头没有 alpha。**

- 多单方向：PF 1.45、EV +0.16pt，跨年稳健（2021/2022/2024 正贡献）。
- 空单方向：PF 0.72、EV -0.12pt，**负期望**；尤其 2023 年空单 12 笔 PF 仅 0.44。
- 之前"全多单 PF 1.50"的高绩效，**恰恰是 sign bug 意外地把亏损的空头信号全部过滤掉**造成的假象——它不是 bug 的"收益"，而是 bug 掩盖了空头方向的真实短板。

**结论**：
1. 修复后策略恢复双向，但整体 PF 从 1.50 降到 1.10，test PF 0.62（样本外转弱）。
2. 若要继续使用该策略，应**只保留多头（long-only）**，并把"空头无 alpha"作为显式结论写进文档，而不是靠 bug 隐性过滤。
3. 若要保留双向，需要为空头单独寻找额外的过滤条件（如 4H 门、事件过滤），否则空头是纯拖累。
