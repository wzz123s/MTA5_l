# 宏观数据与消息面影响测试计划（MT5 财经日历 × 策略研究）

> 版本：v1.0 ｜ 状态：计划 + 数据管线已启动 ｜ 范围：黄金 XAUUSD 4 套策略 + 原油 USOIL 2 套策略

## 1. 研究目标

1. **量化验证**：美债（收益率）、非农（NFP）、CPI、FOMC 等宏观数据发布前后，现有策略的交易表现（胜率、盈亏比、期望值）是否有系统性差异。
2. **机制确认**：高影响事件是否确实引起 XAUUSD / USOIL 的波动率尖峰（用 K 线数据验证，而非仅凭直觉）。
3. **改进评估**：设计"事件过滤 / 事件避险"变体（如事件窗口内不开仓、事件前强制平仓），回测对比基线，判断能否改善收益、回撤和稳定性。
4. **落地决策**：给出明确的"是否/如何把宏观日历接入实盘 EA"结论与实现方案。

## 2. 数据源（已验证的环境事实）

| 数据 | 来源 | 状态 |
|---|---|---|
| 财经日历事件+实际/预期/前值 | **MT5 终端内置日历**（MQL5 的 `CalendarValueHistory` + `CalendarEventById` + `CalendarCountryById`） | ✅ 环境可用（Python 包无日历 API，已用 MQL5 EA 方案打通） |
| 价格 K 线 | 项目已有 `data/raw/mt5_history/*` 各品种 M15~H6 | ✅ 已有 |
| 交易清单 | `observation_dashboard/*/trades_snapshot.csv`（6 套策略，2018~2026） | ✅ 已有 |
| 备选/校验源 | FRED（美国宏观实际值）、已知发布时刻规则（8:30 ET 等） | 按需启用 |

**MT5 日历数据字段**（本终端 build 6140 实测探测）：
- 值：`event_id, time, period, revision, actual/forecast/prev/revised_prev_value, impact_type`（LOW/MEDIUM/HIGH）
- 事件：`name`（终端语言本地化名称）、`importance`（0-100）、`sector/frequency/time_mode/unit/country_id`
- 国家：`name/currency`（经 `CalendarCountryById`）
- 数值为放大 1e6 的整数存储，读取后需还原

## 3. 核心假设（待检验）

- H1：高影响事件（impact=HIGH，如 NFP/CPI/FOMC）前后 ±N 小时开仓的交易，其分布显著区别于其他时段（更差或更好）。
- H2：事件发布瞬间及之后 1-2 小时，XAUUSD/USOIL 的 |收益率| 显著高于基线 → 策略的固定止损易被扫损。
- H3：现有策略的入场信号在事件窗口内并不稀少 → 过滤不会损失过多机会；或过滤后净收益提升。
- H4：原油策略（USOIL2H/USOIL4H）对 EIA 原油库存、OPEC 等事件更敏感；黄金策略对 USD 利率/通胀事件更敏感。

## 4. 实验设计

### 阶段 0：数据采集（已完成设计，正在执行）
- [x] 探测 MQL5 日历结构体字段（build 6140）
- [x] `ExportCalendar_EA.mq5` 编写（按月分块导出 2019→今，UTF-8 CSV）
- [ ] 完成导出并核对深度（验证 2018 年是否可回溯；不足则补 FRED）
- [ ] 事件时间对齐校验：NFP/CPI 应落在 12:30/13:30 UTC（8:30 ET）附近，FOMC 在 18:00/19:00 UTC

### 阶段 1：基线统计
- 每套策略：总交易数、胜率、平均盈亏（点数）、盈亏比、利润因子、按年分布、最大回撤。
- 输出 `baseline_*.csv` + 汇总表，作为所有对比的参照系。

### 阶段 2：事件邻近度分析（事件 × 交易）
对每笔交易计算：
- `nearest_high_event_gap_h`：开仓前最近的高影响事件相隔小时数（负=事件在开仓前）
- `event_within_trade`：持仓期间是否有高影响事件
- `event_after_open_h`：开仓后最近事件的小时数
- 事件类型（CPI/NFP/FOMC/利率/GDP/失业/EIA 库存/OPEC/...）、重要性、币种、surprise（实际 vs 预期）

分组对比（每个分组 vs 基线）：
- 窗口：±1h / ±2h / ±4h / ±8h / ±12h / ±24h 内开仓
- 维度：全部高影响事件、按事件类型、按币种（USD 为主）、按 surprise 方向
- 指标：胜率、平均盈亏、期望值、样本量
- 检验：置换检验 / bootstrap 置信区间（p<0.05，多重比较用 Benjamini-Hochberg 校正）

### 阶段 3：波动率机制验证
- 从 M30/H1 K 线计算事件发布 ±30m/±60m/±2h 窗口内平均 |收益率| 与全样本基线对比（倍数关系）。
- 验证"事件=波动尖峰"是否成立、强度、衰减速度 → 支撑止损/仓位设计的量化依据。

### 阶段 4：改进变体回测（在交易清单上模拟，因果口径无未来函数）
变体（每套策略独立测试，少量预注册变体防过拟合）：
1. **V1 开仓过滤**：距高影响事件 < T 小时（T∈{1,2,4,8}）不开新仓
2. **V2 事件平仓**：持仓期间遇到高影响事件，在事件时刻按市价平仓（模拟滑点：±0.5×点差）
3. **V3 组合**：V1+V2
4. **V4 动态仓位**：事件窗口内仓位减半（保留信号、降低风险）

评估：期望值变化、胜率变化、最大回撤变化、年度一致性（至少 4/6 年同向）、bootstrap CI。

### 阶段 5：结论与实盘接入
- 对每个变体给出"采纳/不采纳/条件采纳"结论与理由。
- 若采纳：给出 EA 改造方案（MQL5 日历 API 实时查询 `CalendarValueLast`，事件窗口内禁止开仓/强制平仓），并在模拟盘观察 2-4 周。

## 6. 风险与注意

1. **日历历史深度**：MT5 日历可回溯年限待实测；若不足 2018，早期年份用 FRED/已知发布时间补齐（仅影响 BiasReversal 的早期样本）。
2. **事件时间语义**：calendar 的 `time` 与 K 线时间戳的时区对齐需用已知事件校准（阶段 0 最后一步）。
3. **模拟滑点**：事件瞬间价差可能扩大，V2 需保守估计。
4. **过拟合**：变体数量受限、预注册假设、bootstrap 检验、年度一致性要求。
5. **终端干扰**：导出/部署需要重启 MT5 终端（项目既有流程一致），注意避开实盘持仓关键时点。
