## 一、背景：Gold_DataEvent 总览归零

- 现象：observation_dashboard 总览 Gold_DataEvent 从基线 405 笔骤变为 **0 笔 / 0 pts / $500**，看起来策略"归零"；
- 数据源正常：`gold_dataevent_live` M30 90,712 根刷新到最新；EA 已挂载（10 个 EA 加载），signals_export 逐 bar 持续写入（决策 FAIL/SKIP，6H 门未过，尚无开仓）；
- 根因：`_live_active()` 只要 signals_export 有行就切"实时口径"，而 **trade_ledger 为空（无已平虚拟仓）** → 返回 0 笔；
- 注：该 0 状态是 2026-09-01 21:00 适配器改"实时优先"时的有意设计（文档称"诚实状态"），但总览行完全丢失基线上下文，易被误读为策略失效。

## 二、修复

`build_gold()` / `build_oil()`：**仅当 trade_ledger 真实积累平仓数据行后才切实时口径**；
EA 在跑但无平仓记录期间，总览行回退显示**回测基线**（Gold 405 笔/PF 1.753、Oil 58 笔）。

```python
def build_gold():
    led = _read_live_csv("Gold_DataEvent_trade_ledger.csv")
    if led is not None and len(led) > 0:   # 只有 ledger 有平仓记录才实时
        st = _st_from_live_ledger(led, "gold")
        return st, led, _live_tf_frame("Gold_DataEvent")
    return _build_backtest_gold()           # 否则回退基线
```

> 说明：实时"诚实状态"仍在各策略 detail 的 `live_snapshot()` 块保留（显示已平仓 0 笔、逐 bar 评估数、事件门状态），
> 只是总览行不再显示裸 0，避免与"数据丢失/策略失效"混淆。
