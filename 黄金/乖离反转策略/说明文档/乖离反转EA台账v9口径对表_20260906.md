> 原则：**以 python v9 为口径基准**，EA 增加"台账回放模式"逐行镜像，改动不触碰实盘交易路径。

## 0. 时间轴约定（对表前提，已用 A1/A2 实证背书）

- python 读原始 CSV 后统一 closed_time=True：行"时间"= MT5 bar open + TF（即 bar close）。EA 侧用同一终端数据的 `iTime`（bar open）整数做换算，两轴直接相等（A1/A2 同法达到 94%+ matched，无需偏移换算）；
- 样本实证（data/raw/XAUUSDm_H1.csv）：trade 行 signal=2015-05-13 01:00 / entry=4716.79 = **00:00 bar 的 open**；exit_time=03:00 / exit=4702.155 = **[02:00,03:00) bar 的 open**（死叉回溯填 open，见 §5）；pnl=-19.35179 = (4702.155-4716.79) - 4716.79×0.001。

## 2. 对表证据

- SMMA 公式：python processing/smma.py 与 EA CalcSmmaArray 逐行同构（seed=mean、alpha=1/N）→ 可直读复用；
- 死叉回溯填 open：2026-05-13 样本 exit=4702.155 恰为 [02:00,03:00)（exit_time=03:00 该行）的 open，非 close(4691.957) 也非下一行 open(4691.69) → **python 死叉按 opens[i] 填**（实盘口径差异点，须在回放中显式保留）；
- 成本：同一样本 (4702.155-4716.79)-4716.79×0.001=-19.35179 与 CSV pnl 完全吻合 → cost 双边 0.1% 入式；
- 门边界：python bisect 允许 close_time==C_i 的 H6 参与（刚收盘），EA 回放需在**同一行**先追加再取门（H6 与 H1 边界重合时的顺序敏感点）。

## 3. 已确认的 EA 代码改动清单（对照本表）

1. 台账列改为：signal_time, dir, entry, stop, exit_time, exit, exit_reason, pnl_points, holding_bars, side, entry_time（对齐 v9 前 9 列同名同序）；

3. 回放引擎 RpReplayTick：逐新 H1 行追加全序列 SMMA（H1 s5/s13；H6 s5/s55）→ 每行执行 python 一次迭代（开/平规则见 §1 表）；
4. 时间列全部 bar 时间戳（signal=C_{entry-1}、entry_time=入场行 open、exit=C_i），实盘旧行保留近似值但**不参与对账**；
5. SimMode 下台账 FILE_WRITE 截断（每次回测清空，沿用 ABC BUG-11b 正确做法）。

- 做空/镜像分支（EnableShort / LongMode=1）段合并口径未统一（BUG 审查 A），回放仅覆盖默认多头路径。
