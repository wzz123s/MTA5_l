# validate 模块总览

这个目录是 `30m2H策略` 的验证脚本主入口。

目标：

- 把大量验证脚本按用途分组。
- 让别人知道每类验证该先看什么。
- 让其他策略复制这套验证层时，有清楚的模块边界。

## 推荐阅读顺序

1. `01_日常验证说明.md`
2. `02_MT5对齐说明.md`
3. `03_实盘证据说明.md`
4. `04_历史专题说明.md`

## 四类验证模块

- 日常验证
  - 面向当前主线的常规检查、差异定位、信号复核、时间语义核对。
- MT5 对齐
  - 面向 Python / MT5 / EA 的映射、资金曲线、成交与退出差异对齐。
- 实盘证据
  - 面向 live gate、手工确认、风险护栏、观察窗口、审批与证据包。
- 历史专题
  - 面向某次阶段性问题、某个版本修复、某个专题实验的集中复盘。

## 使用方式

- 如果你在接当前主线问题：
  - 先看 `01_日常验证说明.md`
- 如果你在做 Python 和 MT5 / EA 对齐：
  - 先看 `02_MT5对齐说明.md`
- 如果你在做实盘前准备或实盘证据收集：
  - 先看 `03_实盘证据说明.md`
- 如果你在追历史问题链路：
  - 先看 `04_历史专题说明.md`

## 对应数据输出

脚本输出统一进入：

- `../../data/validation`

建议保持规则：

- 一个专题一个目录
- 目录名使用 `主题_日期`
- 目录里至少包含：
  - `README.md` 或总结 `.md`
  - 关键 `.csv`
  - 必要时附证据子目录

## 当前维护原则

- 先通过说明文件做模块导航，不轻易改现有脚本路径。
- 新增验证脚本时，先归到四类之一。
- 新增验证结果目录时，命名尽量与脚本主题一致。
