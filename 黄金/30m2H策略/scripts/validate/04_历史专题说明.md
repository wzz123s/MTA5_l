# 04 历史专题说明

适用场景：

- 某一次修复链路持续演进了很多天。
- 某个残差、某个 Stage 问题、某个 shift90 / metadatafix / deinit / bridge 专题需要集中回看。
- 需要按“问题链”而不是按“脚本前缀”理解验证过程。

## 典型脚本特征

- 带日期后缀的 `prototype_*`
- 带日期后缀的 `review_*`
- 带日期后缀的 `refine_*`
- 带日期后缀的 `replay_*`

## 常见专题

- shift90 / close retry / metadatafix
- runtime stage exit
- M15 slot1
- deinit / stage state
- P0 / P1 bridge
- trigger family / mapping unique conflicts

## 对应常见输出目录

- `data/validation/*_20260713`
- `data/validation/*_20260714`
- `data/validation/*_20260715`
- `data/validation/*_20260716`
- `data/validation/stage_state_*`

## 阅读建议

1. 先找专题目录
2. 再找对应 `review_*` 主脚本
3. 再看它依赖的 `prepare_* / prototype_* / simulate_* / map_*`
4. 最后回看总结报告和关键 CSV

## 给其他策略复用时

其他策略不需要照搬所有历史专题脚本，但应该照搬这种做法：

- 一个重要问题链，拆成多个可回放步骤
- 每一步落一个独立结果目录
- 最后有一份 review 级别总结
