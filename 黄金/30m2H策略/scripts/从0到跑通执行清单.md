# 从 0 到跑通执行清单

这份清单是给“要直接照着跑”的人准备的。

## 第 1 步：先读文档

按顺序看：

1. `../README.md`
2. `../说明文档/01_总览说明/策略说明.md`
3. `../说明文档/01_总览说明/一次性执行计划.md`
4. `README.md`
5. `../data/README.md`

## 第 2 步：确认输入数据

检查：

- `../data/raw`
- 如果需要完整工程输入，再看：
  - `../参考实现工程/base_data`

目标：

- 明确原始数据是否齐全。

## 第 3 步：跑数据源脚本

目录：

- `data_source`

目标：

- 同步或构建原始数据到 `../data/raw`

## 第 4 步：跑预处理脚本

目录：

- `prepare`

目标：

- 从 `../data/raw` 生成 `../data/processed`

## 第 5 步：跑信号脚本

目录：

- `signals`

目标：

- 生成：
  - `../data/signals`
  - 必要时生成 `../data/signals_mt5`

## 第 6 步：跑验证脚本

目录：

- `validate`

建议顺序：

1. 先看 `validate/README.md`
2. 先跑日常验证
3. 再跑 MT5 对齐
4. 有实盘需求时再进入实盘证据模块

目标：

- 把结果统一落到 `../data/validation`

## 第 7 步：整理输出

目录：

- `bundle`

目标：

- 生成最终文档包或策略包

## 第 8 步：如果要接 MT5 / EA

不要直接从这里猜结构，转去看：

- `../参考实现工程/README.md`
- `../参考实现工程/auto_trade`

## 跑通标准

满足下面几项，就算跑通：

- `data/raw` 有输入
- `data/processed` 有中间表
- `data/signals` 有主线结果
- `data/validation` 有验证结果
- 目录结构仍然清晰，没有把临时产物混进说明层
