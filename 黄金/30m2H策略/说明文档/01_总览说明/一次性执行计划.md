# 一次性执行计划

这份计划的目标是让任何人拿到 `30m2H策略` 之后，可以按固定顺序一次性完成：

- 读懂策略
- 准备数据
- 跑出信号
- 完成验证
- 整理产物
- 复用到其他策略

## 总体原则

- 先读说明，再跑脚本。
- 先固定输入，再生成中间表。
- 先产出主线信号，再做对齐验证。
- 先完成研究验证，再进入 EA / MT5 / 实盘链路。

## 阶段 1：理解策略定义

目标：

- 明确 `30m2H` 的交易逻辑和流程边界。

必读文件：

- `策略说明.md`
- `策略执行说明.md`
- `脚本与数据接口说明.md`
- `M15买卖逐步判定流程.md`

完成标准：

- 能说清楚主周期、辅助周期、入场、过滤、退出、仓位规则。

## 阶段 2：准备数据输入

目标：

- 确认原始数据和标准化数据入口。

入口目录：

- `data/raw`
- `scripts/data_source`
- `scripts/prepare`

完成标准：

- `data/raw` 中已有本策略需要的原始数据。
- `data/processed` 中已有可供信号脚本直接使用的标准化结果。

## 阶段 3：生成主线信号

目标：

- 生成 Python 主线结果与必要的 MT5 数据版本结果。

入口目录：

- `scripts/signals`
- `data/signals`
- `data/signals_mt5`

完成标准：

- 生成候选信号。
- 生成 Layer3 入选信号。
- 生成执行交易结果。

## 阶段 4：完成验证

目标：

- 确认主线结果、差异定位、Python / MT5 / EA 对齐状态。

入口目录：

- `scripts/validate`
- `data/validation`

优先顺序：

1. 日常验证
2. MT5 对齐
3. 实盘证据
4. 历史专题

完成标准：

- 能定位当前差异是否来自输入、映射、退出、执行模型或实盘链路。

## 阶段 5：整理交付产物

目标：

- 把说明、脚本、数据、验证结果组织成可交付结构。

入口目录：

- `说明文档`
- `scripts`
- `data`
- `参考实现工程`

完成标准：

- 别人打开目录后，不需要猜“从哪里开始、跑什么、看什么”。

## 阶段 6：复制到其他策略

目标：

- 用 `30m2H策略` 作为母版创建新策略。

优先复制：

- `说明文档`
- `scripts`
- `data`
- `复用模板`

按需参考：

- `参考实现工程`

完成标准：

- 新策略目录同样具备“说明、脚本、数据、验证、落地”五层结构。

## 推荐主入口

- 顶层总入口：
  - `README.md`
- 一次性跑通入口：
  - `scripts/从0到跑通执行清单.md`
- 完整母版入口：
  - `参考实现工程/README.md`
