# M15 / H2 提前触发测试计划

> 创建时间：2026-06-26
> 目的：把 M15 和 H2 从“事后过滤”改成“提前触发/提前确认”的研究方向，优先测试是否能增加有效交易机会。

## 1. 核心思路

当前 `M15 close-side` 是硬过滤：先得到 M30/H2 的 80 笔候选，再用 M15 删除不同侧信号，所以结果只能减少到 54 笔。

新的研究方向不是过滤，而是提前触发：

| 层级 | 原问题 | 新思路 |
| --- | --- | --- |
| M30 入场层 | 等 M30 收完后，价格可能已经走太远，止损超出 spec | 把一根 M30 拆成两根 M15，用 M15 提前入场或救回原本超止损的机会 |
| H2 过滤层 | 等 H2 完整确认后，趋势过滤可能太慢 | 把一根 H2 拆成四根 M30，用 H2 内部 M30 进展提前确认 Layer 1 / Layer 3 |

本计划先只做 Python 侧研究，不接 EA，不跑 MT5。

## 2. 固定基线

先固定当前已验证的主结构，避免同时移动太多变量。

| 项目 | 基线 |
| --- | --- |
| 品种 | XAUUSDm |
| Layer 1 | H2 `|Bias_55| > 3.0%` |
| Layer 2 | M30 `pre_cross + cross + post_n(2-6)` |
| pre_cross | close 穿越 SMA13，SMA5 仍在另一侧，gap `<= 0.300%` |
| stop spec | `[5, 35] pt` |
| Layer 3 | H2 `Bias_5 top30` |
| 加 M15 前结果 | 80 笔，WR 65.0%，PF 8.06，EV +33.27pt，PnL $2662，MaxCL 5 |
| 旧 M15 close-side 结果 | 54 笔，WR 68.5%，PF 13.50，EV +43.78pt，PnL $2364，MaxCL 5 |

注意：旧 `M15 close-side` 只作为对照，不作为本轮主线目标。

## 3. M15 early-entry 测试

### 3.1 目标

验证 M15 是否能在 M30 正式信号形成前提前入场，从而：

- 增加交易数量。
- 降低入场后止损距离。
- 救回 M30 收盘时已经超过 stop spec 的机会。
- 不显著恶化 PF、EV、MaxCL。

### 3.2 数据映射

每根 M30 对应两根 M15：

| M30 内部位置 | 含义 |
| --- | --- |
| `m15_half1` | M30 前半段 M15 |
| `m15_half2` | M30 后半段 M15 |

测试时只能使用当时已经完成的 M15，不能使用完整 M30 结果回头确认提前入场。

### 3.3 变体

| 变体 | 说明 | 预期作用 |
| --- | --- | --- |
| `m15_replace_half1` | 若 M30 信号所在 bar 的前半根 M15 已满足提前条件，用该 M15 close 替代 M30 entry | 不增加信号数，但可能降低止损距离 |
| `m15_replace_any` | 前半或后半任一 M15 先满足条件，就用更早的 M15 close 替代 entry | 不增加信号数，重点看止损距离改善 |
| `m15_add_pre_cross` | M15 出现类似 `pre_cross` 的提前条件时，允许新增一笔 Layer 2 机会 | 增加交易数 |
| `m15_add_cross` | M15 SMA5/13 先穿越时，允许新增一笔 Layer 2 机会 | 增加交易数，但噪音可能更大 |
| `m15_rescue_stop` | 只在 M30 entry 因 stop spec 失败时，检查 M15 提前 entry 是否能通过 `[5,35]` | 专门验证“救回错过机会” |
| `m15_add_rescue_only` | 只把 rescue 成功的 M15 作为新增交易，不扩大所有 M15 触发 | 更保守地增加交易数 |

### 3.4 去重规则

- 同一 M30 bar、同一方向，只保留最早触发的一笔。
- 若 M15 已提前入场，则后续 M30 正式信号不再重复计入。
- 若同一段行情内 M15 连续触发，只保留第一笔，避免把一个波段拆成多笔假增量。

### 3.5 评价指标

| 指标 | 目的 |
| --- | --- |
| 总笔数 | 是否真的增加交易 |
| 新增笔数 | M15 相对 80 笔基线新增多少 |
| rescue 笔数 | 有多少原本因 stop spec 失败的机会被救回 |
| WR / PF / EV / PnL / MaxCL | 基础质量 |
| 平均/中位止损距离 | 是否真正改善过晚入场问题 |
| stop spec 通过率 | M15 是否让更多机会进入 `[5,35]` |
| mode split | 新增机会来自 pre_cross、cross 还是 rescue |
| 训练/验证分段 | 防止只在局部年份有效 |

## 4. H2 early-gate 测试

### 4.1 目标

验证 H2 过滤是否也可以提前确认，而不是等完整 H2 bar 完结后才判断。

这里的思路和 M15 拆 M30 类似：H2 太慢，就把一根 H2 拆成四根 M30，观察 H2 内部走势是否已经足够满足 Layer 1 / Layer 3。

### 4.2 数据映射

每根 H2 对应四根 M30：

| H2 内部位置 | 含义 |
| --- | --- |
| `m30_q1` | H2 第 1 个 M30 |
| `m30_q2` | H2 第 2 个 M30 |
| `m30_q3` | H2 第 3 个 M30 |
| `m30_q4` | H2 第 4 个 M30，接近完整 H2 |

测试时只能使用已经走完的 M30 子段，不能使用最终 H2 close 反推早期判断。

### 4.3 变体

| 变体 | 说明 | 预期作用 |
| --- | --- | --- |
| `h2_early_bias55_q2` | H2 走到第 2 根 M30 时，用临时 H2 close 估算 `Bias_55` 是否已超过阈值 | 提前打开 Layer 1 gate |
| `h2_early_bias55_q3` | H2 走到第 3 根 M30 时提前判断 `Bias_55` | 比 q2 稳一点，仍比完整 H2 更早 |
| `h2_early_bias5_q2` | H2 内部 q2 时估算 `Bias_5` 排名/强度 | 提前做 Layer 3 质量筛选 |
| `h2_early_bias5_q3` | H2 内部 q3 时估算 `Bias_5` | 稳定性可能更好 |
| `h2_early_gate_union` | 完整 H2 gate 或 early gate 任一通过即允许 | 目标增加机会 |
| `h2_early_gate_rescue` | 只救回完整 H2 gate 未通过、但内部 q2/q3 已明显达标的机会 | 更保守地增加机会 |

### 4.4 注意事项

- `SMMA55`、`SMMA5` 的历史值仍来自已经完成的 H2 bar。
- 当前未完成 H2 的 close 用对应 M30 子段 close 代替，只作为临时估算。
- 不能用未来 H2 完整 close 判断早期 q2/q3 是否有效。
- H2 early-gate 主要影响 Layer 1 / Layer 3，不直接改变 M30 入场形态。

### 4.5 评价指标

| 指标 | 目的 |
| --- | --- |
| Layer 1 通过 bar 数 | early gate 是否扩大可交易窗口 |
| 最终交易笔数 | 是否增加交易 |
| 新增/救回笔数 | 相比当前 80 笔基线增加多少 |
| WR / PF / EV / PnL / MaxCL | 基础质量 |
| Bias_55 / Bias_5 分布 | early gate 是否只是放进弱趋势 |
| q2 vs q3 对比 | 判断提前程度和稳定性 |
| 与 M15 early-entry 组合效果 | 两个提前逻辑是否叠加有效 |

## 5. 测试顺序

建议分三轮，不要一开始就把 M15 和 H2 混在一起。

| 顺序 | 测试 | 目标 |
| --- | --- | --- |
| 1 | M15 early-entry 单独测试 | 先验证拆 M30 是否能增加交易和改善止损 |
| 2 | H2 early-gate 单独测试 | 再验证拆 H2 是否能扩大过滤窗口 |
| 3 | M15 early-entry + H2 early-gate 组合测试 | 最后看两个提前逻辑是否能叠加，还是噪音过大 |

## 6. 成功标准

先用宽松标准判断是否值得继续：

- 总笔数相对 80 笔基线有明确增加。
- PF 不低于 5.0。
- EV 不低于 +25pt。
- MaxCL 不超过 7。
- 平均止损距离不高于当前基线。
- 验证段不明显崩坏。

如果某个变体只提高笔数，但 PF/EV/MaxCL 明显恶化，则只保留为历史记录，不进入 EA。
