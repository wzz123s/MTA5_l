# M15买卖逐步判定流程

> 适用范围：`30m2H` 当前主线  
> 当前主线增强：`M15 replace_any + rescue` + `H2 Layer1 q2 early-gate`  
> 目的：把 `M15` 在主线中的作用说清楚，避免再和旧 `M15 close-side` 过滤对照混淆。

## 1. 先说清楚核心原则

- 当前主线的起点仍然是 `H2 Layer1`，不是 `M15`。
- `M15` 在当前主线里不是新增一层过滤器。
- 当前 `M15` 的作用，是把原本属于 `M30 Layer2` 的判定时点拆细。
- 可以把它理解成：
  - 以前是等一整根 `M30` 收完，再判断 `Layer2`。
  - 现在是把这根 `M30` 拆成两个 `M15` 时段，尝试更早在其中一个时段上完成同一套 `Layer2` 判断。
- 一旦这个更早的 `M15` 时点成立，后面的逻辑不变：
  - 止损算法不变
  - `StopSpec` 不变
  - `Layer3` 不变
  - `Stage1 / Stage2 / Stage3` 不变

## 2. 当前主线总链路

```text
H2 Layer1
-> M30 Layer2（用拆细后的 M15 提前处理）
-> Layer3
-> StopSpec
-> 执行与 Stage 退出
```

更细一点：

```text
先看 H2 Layer1 是否通过
-> 通过后，判断当前机会属于 pre_cross / cross / post_n 哪一类
-> 尝试在这根 M30 内更早的 M15 时点上完成该 Layer2 判定
-> 计算与原主线一致的止损
-> 检查 StopSpec [5, 35] pt
-> 检查 Layer3
-> 生成 BUY / SELL 信号
```

## 3. Python 与 EA 的口径差异

### 3.1 Python 研究口径

- `replace_any`
  - 在一根 `M30` 对应的 30 分钟窗口里，顺序扫描两根 `M15`。
  - 只要更早的 `M15` 已经满足该方向条件，而且止损距离合规，就允许把原本的 `M30 entry` 替换为这个 `M15 entry`。
- `rescue`
  - 如果原本 `M30` 候选因为 `StopSpec` 不合格被淘汰，允许尝试在这两根 `M15` 里找一个更早、但仍满足原逻辑且止损合规的 entry，把这笔机会救回来。

### 3.2 EA 实盘口径

- EA 当前不是完整照搬 Python 的“回看两根 M15”。
- EA 当前只执行 `slot1`：
  - 也就是当前这根 `M30` 内第一根已完成 `M15`。
- `slot2` 不单独执行提前单，仍并入正常 `M30 CLOSE` 流程。
- 所以：
  - Python 更像“研究上限”和“时间拆细后的理论最优”
  - EA 更像“实盘可执行、不过度回看”的保守落地版本

## 4. BUY 逐步判定流程

### 4.1 BUY 的公共前提

做多分支无论是 `pre_cross / cross / post_n`，都先满足下面这些原则：

1. `H2 Layer1` 先通过。
2. 当前候选方向必须是 `BUY`。
3. 不是“Layer2 完成后再额外看 M15”，而是直接在拆细后的 `M15` 时点上提前判断这笔 `BUY` 是否已经满足原本的 `Layer2` 条件。
4. 如果提前时点成立，再继续走止损、`StopSpec`、`Layer3`。

### 4.2 BUY - pre_cross 分支

原始 `M30 Layer2` 做多定义：

- 上一根 close 在 `SMA13` 下方或贴下方
- 当前这根 close 站上 `SMA13`
- 同时 `SMA5` 仍在 `SMA13` 下方
- 并且 `gap = |SMA5 - SMA13| / SMA13 <= 0.300%`

当前主线里的提前处理方式：

1. `H2 Layer1` 已通过。
2. 不等整根 `M30` 收完，先看拆细后的 `M15` 时点上，这笔 `pre_cross BUY` 是否已经成立。
3. 如果成立，就把这根 `M15` 当成原本 `M30 Layer2` 的更早判定时点。
4. entry 用这个更早的 `M15 close`。
5. 止损仍按原主线口径：
   - 使用上一段空头段里 `SMA13` 的最低极值。
6. 再检查：
   - `entry > stop`
   - `StopSpec` 在 `[5, 35] pt`
   - `Layer3` 通过
7. 全部通过才生成 `BUY`。

### 4.3 BUY - cross 分支

原始 `M30 Layer2` 做多定义：

- `SMA5` 从下向上穿越 `SMA13`

当前主线里的提前处理方式：

1. `H2 Layer1` 已通过。
2. 在拆细后的 `M15` 时点上，提前判断这笔 `cross BUY` 是否已经满足原本的方向条件。
3. 如果更早的 `M15` 已经能代表这笔向上穿越机会，就用该 `M15 close` 作为更早 entry。
4. 止损仍按原主线口径：
   - 使用上一段空头段里 `SMA13` 的最低极值。
5. 再检查：
   - `entry > stop`
   - `StopSpec` 在 `[5, 35] pt`
   - `Layer3` 通过
6. 通过后生成 `BUY`。

### 4.4 BUY - post_n 分支

原始 `M30 Layer2` 做多定义：

- 最近一次金叉已经发生
- 当前处于金叉后的第 `2-6` 根延续段

当前主线里的提前处理方式：

1. `H2 Layer1` 已通过。
2. 不额外新增过滤，而是在拆细后的 `M15` 时点上，提前确认这笔 `post_n BUY` 是否已经可以成立。
3. 如果这根 `M15` 已经能代表原本这根 `M30` 的延续做多机会，就用它的 close 提前入场。
4. 止损仍按原主线口径：
   - 直接用当前对应的 `SMA13`
5. 再检查：
   - `entry > stop`
   - `StopSpec` 在 `[5, 35] pt`
   - `Layer3` 通过
6. 通过后生成 `BUY`。

## 5. SELL 逐步判定流程

SELL 与 BUY 完全对称，只是方向相反。

### 5.1 SELL 的公共前提

1. `H2 Layer1` 先通过。
2. 当前候选方向必须是 `SELL`。
3. 用拆细后的 `M15` 去提前处理原本属于 `M30 Layer2` 的判定。
4. 之后仍走原主线的止损、`StopSpec`、`Layer3`。

### 5.2 SELL - pre_cross 分支

原始 `M30 Layer2` 做空定义：

- 上一根 close 在 `SMA13` 上方或贴上方
- 当前这根 close 跌破 `SMA13`
- 同时 `SMA5` 仍在 `SMA13` 上方
- 并且 `gap = |SMA5 - SMA13| / SMA13 <= 0.300%`

提前处理方式：

1. `H2 Layer1` 已通过。
2. 先看拆细后的 `M15` 时点上，这笔 `pre_cross SELL` 是否已经成立。
3. 若成立，就用这个更早的 `M15 close` 作为 entry。
4. 止损仍按原主线口径：
   - 使用上一段多头段里 `SMA13` 的最高极值。
5. 再检查：
   - `entry < stop`
   - `StopSpec` 在 `[5, 35] pt`
   - `Layer3` 通过
6. 通过后生成 `SELL`。

### 5.3 SELL - cross 分支

原始 `M30 Layer2` 做空定义：

- `SMA5` 从上向下穿越 `SMA13`

提前处理方式：

1. `H2 Layer1` 已通过。
2. 用拆细后的 `M15` 提前判断这笔 `cross SELL` 是否已经具备原始方向条件。
3. 若成立，entry 前移到更早的 `M15 close`。
4. 止损仍按原主线口径：
   - 使用上一段多头段里 `SMA13` 的最高极值。
5. 再检查：
   - `entry < stop`
   - `StopSpec` 在 `[5, 35] pt`
   - `Layer3` 通过
6. 通过后生成 `SELL`。

### 5.4 SELL - post_n 分支

原始 `M30 Layer2` 做空定义：

- 最近一次死叉已经发生
- 当前处于死叉后的第 `2-6` 根延续段

提前处理方式：

1. `H2 Layer1` 已通过。
2. 用拆细后的 `M15` 提前处理这笔 `post_n SELL`。
3. 若成立，entry 前移到该 `M15 close`。
4. 止损仍按原主线口径：
   - 直接用当前对应的 `SMA13`
5. 再检查：
   - `entry < stop`
   - `StopSpec` 在 `[5, 35] pt`
   - `Layer3` 通过
6. 通过后生成 `SELL`。

## 6. 当前代码里的关键实现点

- 原始三类 `Layer2` 候选生成：
  - Python：`collect_pre_cross_candidates / collect_cross_candidates / collect_post_candidates`
  - 位置：`scripts/_m15_early_entry_test.py`
- `M15` 窗口定义：
  - 一根 `M30` 对应过去 30 分钟内的两根 `M15`
- `replace_any`：
  - 在窗口内顺序寻找更早且合规的 `M15 entry`
- `rescue`：
  - 对原本 `StopSpec` 失败的候选，尝试用更早的 `M15 entry` 救回
- EA 当前实现：
  - 只执行 `slot1`
  - `slot2` 仍回到普通 `M30 CLOSE`
