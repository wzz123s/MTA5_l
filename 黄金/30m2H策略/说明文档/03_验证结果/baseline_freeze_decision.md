## 1. 历史背景

30m2H 存在两个 Python 快照，交易数和收益不一致：

| 快照 | 交易数 | PF | PnL | Layer3 threshold |
| --- | ---: | ---: | ---: | ---: |
| 顶层快照（旧） | 102 | 11.54 | `$2200` | `0.652164` |
| 参考实现工程复跑（旧） | 121 | 2.96 | `$913` | `0.374868` |

2026-08-10 用户确认采用 121 笔参考实现口径。

## 2. 2026-08-11 MT5 数据源迁移

### 2.1 触发原因

按部署达标清单要求，30m2H 需要独立 MT5 API 数据源（与 EA 同源）才能实现逐笔对齐。Phase 1.2 拉取 MT5 数据时发现：

**时区口径不自洽**：
- 服务器实测为 **UTC**（偏移 0）
- 历史口径：M30 prepare `+2h`、M15 `+2h`、H2 `+2h(时区)+2h(bucket→decision)`
- M30 时间轴 (UTC+2) 与 H2 决策时间轴 (UTC+4) 内部差 2h，且均与 EA 图表时间 (UTC) 不一致
- **旧口径无法与 EA 对齐**（时间差 2h）

### 2.2 迁移内容

1. **数据**：MT5 API 拉取 M30 (100,015 bars, 2018-02-22 起) + H2 (26,668 bars) + M15 (99,994 bars, 2022-05-17 起，服务器限制)
2. **时区修正**：prepare/load_m15/H2 时区常量 `+2h → 0`（全 UTC 自洽）
3. **H2 39col 重建**：从新 M30 数据重新生成（旧文件基于 +2h 时间轴，桶偏移 2h）
4. **M30 数据验证**：共同范围 96,483 根 bar 价格 100% 一致（数据质量无问题）

### 2.3 基线变化（121 → 128）

| 指标 | 旧 (121) | 新 (128) | 变化 |
| --- | ---: | ---: | ---: |
| 交易数 | 121 | 128 | +7 |
| 胜率 | 53.7% | 50.8% | -2.9pp |
| PF | 2.96 | 2.71 | -0.25 |
| EV | +37.72pt | +34.38pt | -3.34pt |
| PnL | `$913` | `$880` | -`$33` |
| MaxCL | 8 | 7 | -1 |
| 验证集 PF | 3.67 | 3.19 | -0.48 |
| Layer3 threshold | 0.374868 | 0.372564 | -0.002 |

**差异诊断**（114 笔时间/方向匹配中）：
- PnL 相同：4 笔
- 微小差异 ≤1pt：70 笔（61%）（stop 微差 max 0.75pt）
- 1-5pt：24 笔
- 5-30pt：12 笔
- >30pt（触发翻转）：4 笔（TP vs SL / force vs trail 临界翻转）
- 缺失 7 笔 / 新增 14 笔（H2 桶修正 → Layer1 门控/信号判定变化）

**结论**：差异源于 H2 桶口径修正的自然结果，非数据质量错误（M30 数据 100% 一致）。

## 3. 最终决策

**采用新基线：128 笔 UTC 同源口径。**

理由：
1. 新口径全 UTC 自洽，与 EA 图表时间（UTC）一致 → **逐笔对齐可达成**
2. 数据同源（MT5 API），满足策略生成规则
3. 旧口径（M30+2h/H2+4h）内部不自洽，无法对齐 EA
