# EA stop 与编译版本核查

## 本轮确认

- Python 主线不是简单 `SMA` 口径。
- `processing/prepare.py` 实际调用的是 `processing/smma.py` 的 `calc_smma()`。
- 当前 `auto_trade/30m2H_Strategy_EA.mq5` 里，M30 / H2 / M15 句柄也都使用 `MODE_SMMA`。
- 因此当前残差不能归因于“Python 用 SMA、EA 用 SMMA”。

## 编译版本核对

- `auto_trade/30m2H_Strategy_EA.mq5`
  - 最后修改时间：`2026-07-05 20:12:15`
- `auto_trade/30m2H_Strategy_EA.ex5`
  - 最后修改时间：`2026-07-04 12:07:34`

结论：

- 当前 `mq5` 源码晚于 `ex5` 编译产物。
- 旧 tester 日志对应的很可能不是当前源码版本。
- 在重新编译当前 `mq5` 并生成新日志前，不应继续用旧日志给当前 stop 逻辑下最终结论。

## stop 公式补充判断

- Python 的 `prior_segment_stop()` 已确认没有算错。
- 当前源码中的 `FindStopSMA()` 仍有一个待复核点：
  - 极值循环边界是 `for(int i = seg_start; i < n - 2; i++)`
  - 这对 `2026-02-24 03:00:00` 这笔存在可疑的 `i-1 / i-2` 边界差异
- 但这条判断必须在“重编译后的新日志”下复核，不能继续直接沿用旧 `ex5` 日志。
