# 复刻清单：其他策略落地版

如果你要把 `30m2H` 的完整工程思路迁移成一套新策略，可以按下面清单逐项完成。

## 第一阶段：定义策略

- 明确交易标的。
- 明确主周期和辅助周期。
- 明确入场、过滤、退出、仓位规则。
- 在新策略目录中补一份策略说明文档。

## 第二阶段：建立数据链路

- 准备原始行情到 `base_data` 或 `data/raw`。
- 复制并改造预处理入口。
- 生成标准化主表、派生周期表、上下文表。
- 确认新策略字段命名统一。

## 第三阶段：建立信号链路

- 从 `strategy` 中复制策略框架。
- 从 `processing` / `factors` 中复制通用能力。
- 从 `scripts` 中复制信号导出和参数测试脚本。
- 输出候选信号、最终信号、执行交易结果。

## 第四阶段：建立验证链路

- 复用 `scripts/validate` 的验证思路。
- 对齐 Python 内部结果。
- 对齐不同数据源结果。
- 如果有 MT5 / EA，再对齐 Python 与 MT5 / EA。
- 把验证结果统一输出到数据结果目录。

## 第五阶段：建立执行链路

- 如果只做研究，到这里可以结束。
- 如果要接 MT5 / EA，就参考 `auto_trade`：
  - EA 源码
  - 参数 `.ini/.set`
  - 编译日志
  - 信号导出
  - 运行监控

## 每一层对应参考目录

- 策略规则：
  - `交易规则`
  - `strategy`
- 数据处理：
  - `base_data`
  - `processing`
  - `factors`
- 研究脚本：
  - `scripts`
- 结果验证：
  - `data`
  - `evaluate`
  - `optimize`
  - `shadow_tests`
- 执行落地：
  - `auto_trade`

## 完成标准

- 新策略目录里要能区分“说明、代码、数据、验证、执行”。
- 要能从原始数据走到最终信号。
- 要能把关键结果落成表格和验证文档。
- 如果接 EA，要能跑通导出、编译、回看、监控链路。
