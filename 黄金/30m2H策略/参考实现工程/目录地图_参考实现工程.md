# 目录地图：参考实现工程

这个文件的目标是帮助别人快速理解本目录每一层在完整流程里扮演什么角色。

## 完整流程视角

1. 先定义策略规则
   - 看 `交易规则`
   - 看 `strategy`
2. 再准备基础数据
   - 看 `base_data`
   - 看 `processing`
   - 看 `factors`
3. 再生成研究与验证产物
   - 看 `scripts`
   - 看 `evaluate`
   - 看 `optimize`
   - 看 `shadow_tests`
   - 看 `data`
   - 看 `images`
4. 最后接执行端
   - 看 `auto_trade`

## 目录职责

- `strategy`
  - Python 策略类与评分逻辑，是“策略定义层”的核心。
- `processing`
  - 数据预处理、方向、极值、平滑、段过滤等，是“信号输入层”。
- `factors`
  - 因子计算逻辑，服务于预处理和策略判断。
- `base_data`
  - 基础 CSV 数据和数据构建脚本，是研究入口数据源。
- `scripts`
  - 主线研究脚本、参数测试脚本、认证脚本、差异分析脚本。
- `data`
  - 原始数据、中间产物、结果表、交易明细、图表输入。
- `evaluate`
  - 回测指标、结果统计、可视化辅助。
- `optimize`
  - 参数搜索和稳定性分析。
- `shadow_tests`
  - 旁路实验和多周期对照验证。
- `images`
  - 图表、资金曲线、调试图片输出。
- `auto_trade`
  - EA、MT5、部署、监控、日志、执行验证。
- `交易规则`
  - 原始规则说明文档，是策略业务语义的来源。

## 复刻新策略时的最小必看

- `strategy`
- `processing`
- `base_data`
- `scripts`
- `data`

## 复刻新策略时的扩展必看

- 如果要做 MT5 / EA：
  - `auto_trade`
- 如果要做严格对齐验证：
  - `shadow_tests`
  - `evaluate`
  - `optimize`

## 不建议当作主入口的内容

- `progress.md`
- `task_plan.md`
- `findings.md`
- 历史日志、编译日志、旧输出快照

这些文件保留是为了还原工作过程，不适合作为新策略模板的第一入口。
