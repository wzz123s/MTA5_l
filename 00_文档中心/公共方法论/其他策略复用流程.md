# 其他策略复用流程

这个文件的目标不是解释 `30m2H` 本身，而是规定如何把这套方法复制成另一套策略。

## 新策略目录骨架

```text
新策略文件夹/
  README.md
  说明文档/
    00_策略生成规则/
    01_总览说明/
    02_策略流程/
    03_验证结果/
    04_项目清单/
  scripts/
    data_source/
    prepare/
    signals/
    validate/
    bundle/
  data/
    raw/
    processed/
    signals/
    validation/
  参考实现工程/
  归档/
```

## 硬规则：原始数据必须独立

- 不同策略必须使用不同的原始行情数据源生成。
- 新策略不得直接复用 `黄金/30m2H策略/参考实现工程/base_data` 或其他策略目录里的 raw 文件作为正式生成源。
- 每个策略的 `data/raw` 必须保留 `raw_source_manifest.json`。
- 如果两个策略的 raw source path 或 sha256 相同，视为同源数据，不能同时作为“不同策略”的正式认证结果。
- `30m2H` 只能作为代码结构、验证方法和 EA 实现参考，不能作为新策略的默认 raw 数据来源。
- 没有 raw manifest 的结果只能标记为迁移/脚手架/旧结果，不能标记为正式策略结果，也不能进入 MT5 部署认证。

## 推荐迁移顺序

1. 先写策略总说明：明确入场条件、过滤条件、退出条件、仓位规则、时间周期。
2. 准备策略专用原始数据：用 `scripts/data_source/sync_raw_data.py --source <专用raw>` 写入 `data/raw` 并生成 manifest。
3. 做预处理脚本：在 `scripts/prepare` 中生成标准化主表、上下文表、派生周期表。
4. 写信号脚本：在 `scripts/signals` 中输出候选信号、最终信号、执行交易结果。
5. 写验证脚本：在 `scripts/validate` 中对齐 Python、MT5、EA、时间语义、信号差异。
6. 最后接执行端：如果需要 EA、实盘或 MT5 联动，再参考 `参考实现工程/auto_trade`。

## 从 30m2H 重点参考什么

- 参考策略说明：`说明文档/01_总览说明/策略说明.md`
- 参考流程拆解：`说明文档/02_策略流程`
- 参考脚本分层：`scripts`
- 参考数据分层：`data`
- 参考完整工程实现：`参考实现工程`

## 复用时必须替换的内容

- 交易标的
- 原始数据源和 `raw_source_manifest.json`
- 主周期与辅助周期
- 指标参数
- 候选信号筛选逻辑
- Stage 规则或退出规则
- 验证基准和目标指标

## 不建议直接照搬的内容

- `30m2H` 专属命名
- `30m2H` 原始行情文件
- 历史对齐残留文件
- 老版本验证产物
- `归档` 里的旧资料

## 最终验收标准

- 只看目录结构，就能知道“说明、代码、数据、结果”分别在哪里。
- 只看 `README.md`，就知道先读什么、后跑什么。
- 只看 `scripts` 和 `data`，就能复现主要流程。
- 只看 `data/raw/raw_source_manifest.json`，就能确认本策略原始数据来源。
- 需要 EA/MT5 时，能在 `参考实现工程` 找到完整落地做法。
